# 문제 해결

문제가 생기면 설정 파일을 먼저 수정하지 말고 아래 순서로 확인하세요.

## 1. 상태와 진단

서버:

```bash
sudo frpctl show version
sudo frpctl show status
sudo frpctl doctor
```

클라이언트:

```bash
sudo frpctl show status
sudo frpctl show services
sudo frpctl show info
sudo frpctl doctor
```

## 2. 클라이언트가 서버에 안 보임

서버에서:

```bash
sudo frpctl show enrollments
sudo frpctl show clients
```

확인할 항목:

- Enrollment credential 만료 여부
- 클라이언트가 올바른 public endpoint를 사용하는지
- TCP/443 및 enrollment endpoint 도달 여부
- 클라이언트의 시간 오차가 과도하지 않은지

## 3. 클라이언트는 보이지만 SSH가 안 됨

먼저 클라이언트 로컬에서 대상 서비스가 실제로 열려 있는지 확인하세요.

```bash
ss -lntp | grep ':22'
```

그 다음:

- `show client <ID> services`로 공개 포트 확인
- 외부 방화벽이 해당 `6000-6098` 포트를 허용하는지 확인
- LAN target이면 클라이언트에서 target IP/port로 직접 연결 가능한지 확인

## 4. DNS 이름만 실패

IP로는 되고 hostname으로 실패한다면 FRP보다 DNS를 먼저 확인하세요.

```bash
getent hosts fw.example.com
```

public hostname은 사용자 편의용 별칭이며 FRP의 CLIENT ID나 control identity를 바꾸지 않습니다.

## 5. HTTPS만 인증서 오류

FRP Auto Deploy의 HTTPS 서비스는 TCP passthrough입니다. 브라우저가 보는 인증서는 실제 target 애플리케이션의 인증서입니다. 광고하는 hostname이 인증서 SAN에 포함되어 있는지 확인하세요.

## 6. NAT 환경

방화벽/NAT 뒤 서버는 public control/enrollment 포트가 내부 listen 포트로 정확히 DNAT되어야 합니다. published service 포트는 가능하면 1:1로 유지하세요.
