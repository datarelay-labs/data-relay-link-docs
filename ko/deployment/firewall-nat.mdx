# 방화벽 & NAT

NAT는 별도 배포 모드가 아닙니다. Direct 서버는 공인 IP를 직접 가질 수도 있고 외부 방화벽/NAT 뒤에 있을 수도 있습니다.

## 공인 IP 직접 연결

Direct 기본 인바운드:

```text
443         FRP control
6099        Enrollment / management HTTPS
6000-6098   Published services
```

## 방화벽/NAT 뒤 서버

예:

```text
Internet
   |
203.0.113.10
Firewall / NAT
   |
192.0.2.50
FRP Auto Deploy Server
```

외부 포트를 내부 기본 포트로 변환할 수 있습니다.

```text
203.0.113.10:8443       -> 192.0.2.50:443
203.0.113.10:9443       -> 192.0.2.50:6099
203.0.113.10:6000-6098  -> 192.0.2.50:6000-6098
```

클라이언트는 항상 **외부에서 보이는 public endpoint**를 사용해야 합니다.

## 공개 서비스 포트

가능하면 published service는 외부/내부 포트를 1:1로 유지하세요.

```text
Public 6001 -> Internal 6001
```

그래야 서버 registry의 영구 포트 예약과 실제 인터넷 접속 포트가 일치합니다.

## 책임 경계

FRP Auto Deploy가 자동으로 설정하지 않는 항목:

- AWS Security Group
- OCI Security List
- 외부 방화벽/NAT
- UFW/firewalld/iptables
- SSH 계정과 키

## 내부에서 public hostname으로 접근

방화벽의 hairpin NAT 지원 여부에 따라 실패할 수 있습니다. 필요한 경우 hairpin NAT 또는 split DNS를 사용하세요.
