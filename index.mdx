# FRP Auto Deploy

**Secure remote access to systems behind NAT and firewalls — without VPNs, inbound client firewall changes, or hand-written FRP configuration.**

FRP Auto Deploy is a lightweight deployment and operations layer built on the official `fatedier/frp` binaries. It keeps FRP as the tunnel engine and adds secure enrollment, persistent client identity, service management, public-port allocation, lifecycle controls, diagnostics, backup/restore, and the `frpctl` operator CLI.

## What you can do

- Connect remote Linux systems that sit behind NAT or a firewall
- Publish SSH, HTTP, HTTPS passthrough, and custom TCP services
- Publish services running on the client itself or on other LAN hosts reachable from that client
- Enroll clients with a server-generated Zero-Touch command
- Keep client identity and public service ports stable across normal updates and reboots
- Manage daily operations through `sudo frpctl`
- Run either the default Direct deployment or the optional Enterprise single-443 mode

## How it works

```text
Internet / Operator
        |
        v
+-----------------------+
| FRP Auto Deploy       |
| Server / Public entry |
+-----------+-----------+
            ^
            | outbound FRP control tunnel
            |
   +--------+--------+
   |                 |
   v                 v
Client A           Client B
behind NAT         behind NAT
   |                 |
SSH / HTTPS       LAN SSH / HTTP
```

The remote client initiates the connection toward the FRP server. In normal deployments, the client does not need its own public IP, inbound NAT rule, or inbound firewall opening for the published service.

## Current release

- **Stable project release:** v2.1.2
- **Pinned and tested FRP:** v0.70.1
- **Primary stable client scope:** Linux/systemd
- **Default deployment mode:** Direct
- **Optional deployment mode:** Enterprise single-443

Windows and macOS client automation are development targets, but they are **not stable-supported in v2.1.2**.
