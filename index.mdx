# FRP Auto Deploy

**Secure remote access to systems behind NAT and firewalls — without VPNs, inbound client firewall changes, or hand-written FRP configuration.**

FRP Auto Deploy is a lightweight deployment and operations layer built on the official `fatedier/frp` binaries. FRP remains the tunnel engine; FRP Auto Deploy adds secure enrollment, persistent client identity, service management, public-port allocation, lifecycle controls, diagnostics, backup/restore, and the `frpctl` operator CLI.

## The basic idea

```text
                       Internet / Operator
                               |
                               v
                    +-----------------------+
                    | FRP Auto Deploy       |
                    | Server / Public entry |
                    +-----------+-----------+
                                ^
                                | outbound FRP tunnel
               +----------------+----------------+
               |                                 |
        +------+-------+                  +------+-------+
        | Client A     |                  | Client B     |
        | behind NAT   |                  | behind NAT   |
        +------+-------+                  +------+-------+
               |                                 |
       localhost services                 reachable LAN hosts
        SSH / HTTPS / TCP                  SSH / HTTP / TCP
```

The remote client initiates the connection toward the FRP server. In normal deployments the client does not need its own public IP, inbound NAT rule, or inbound firewall opening for the published service.

## What it gives you

- Zero-Touch or manual client enrollment
- Stable CLIENT ID independent of hostname/IP changes
- SSH, HTTP, HTTPS passthrough, and custom TCP publishing
- Multiple services per client
- Access to LAN services reachable from the client
- Persistent public service-port reservations
- Clear disable / release / revoke lifecycle semantics
- Read-only diagnostics with `frpctl doctor`
- Backup / restore and controlled updates
- Direct and Enterprise single-443 deployment modes
- Optional DNS hostname for user-friendly published-service access

## Current stable baseline

| Item | Current |
| --- | --- |
| Stable project release | **v2.1.2** |
| Project version on `main` | **2.1.3** |
| Pinned / tested FRP | **v0.70.1** |
| Stable client scope | **Linux/systemd** |
| Default deployment | **Direct** |

Windows and macOS client automation are development targets, but they are **not stable-supported in the current stable release**.
